# H1 Tier-Preserving Compiled-Note Archives Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make compiled notes use one canonical tier-bearing archive representation and a crash-resumable reconciliation loop that never downgrades, deletes, misattributes, or leaks a system note.

**Architecture:** A pure archive codec in `src/util/compiled-note-archive.ts` owns canonical bytes, UUID paths, source parsing, and compiled-note recognition; it is deliberately neutral so both `src/pipeline/notes.ts` and `src/db/repo.ts` can consume the same contract without an import cycle. The notes pipeline enumerates recovery files, recognized pages, and current candidates into one identity-keyed work set, then reconciles database page, archive, and chunks from either the durable recovery record or the persisted page. `brainSync()` treats an existing `dream:notes` row as compiler-owned, applies the same fail-closed tier evidence, and exempts it from archive-absence soft deletion.

**Tech Stack:** Bun/TypeScript, PostgreSQL 16 + pgvector, raw parameterized SQL in `src/db/repo.ts`, `node:crypto`, `node:fs/promises`, existing markdown chunker/indexer, offline `bun test`.

## Global Constraints

- Start `codex/hardening-note-tier` only from the exact binding-reviewed H3 branch SHA,
  after H2 and H3 are integrated.
- Use the pinned ignored worktree `.claude/worktrees/hardening-note-tier`, record its initial
  head as `START_SHA`, and scope every status, ledger, diff, gate, and review command to that
  worktree.
- Consume H3's exported canonical `config.dataDir`; recovery lives only at `<config.dataDir>/tmp/compiled-notes` and archives only at `<config.dataDir>/brain`.
- Preserve I1 local-first, I3 tiered egress, I4 files/archive + rows/state + database/index, I5 provenance, I7 honest results, and I8 content-free audit.
- The canonical UTF-8 byte form is exactly `---\ntitle: ${JSON.stringify(title)}\ntier: ${tier}\n---\n${bodyWithoutTerminalNewlines}\n`.
- Normalize CRLF and CR to LF, remove only terminal newline characters from the body, and preserve all other bytes including trailing spaces.
- New note paths are `derived/notes/<kind>/<readable-slug>--<full-entity-uuid>.md`; the UUID, not the slug, owns identity.
- Existing slug-only paths are never automatically renamed, overwritten by another entity, or deleted.
- H1 leaves current candidate generation person-only. `org` UUID/marker archives are
  recognized and repairable, but H1 does not add org distillation.
- The authoritative tier is a max-only floor across the latest existing page tier, every
  existing page-chunk tier, every compiled-page edge tier, current entity-cluster tier when
  present, and tiers of source chunk UUIDs in the persisted Sources block; any unresolved
  listed source or absence of resolvable source tiers fails closed to tier 2.
- For H1 tier evidence, `SELECT ... FOR UPDATE` locking, promotion, changed-row counts,
  verification, and idempotence, a compiled-page edge for `pageId` means exactly
  `((source_table = 'pages' AND source_id = pageId) OR
  (src_type = 'page' AND src_id = pageId))`. Both arms remain parameterized and enclosed by
  the outer parentheses before any `AND tier ...` condition. The second arm preserves H5's
  canonical-parent compatibility for historical edges whose provenance remains
  `source_table='chunks', source_id=chunkId`; a dst-only edge whose unrelated source merely
  points to the compiled page is never captured.
- The archive is never authoritative for a compiled-note tier.
- A durable recovery record is converged once before current freshness is reconsidered, even when the page is absent or the entity fell below the candidate threshold.
- A source snapshot newer than a recovery marker may cause at most one additional distillation in that run; a second concurrent source change is deferred to the next run after the second durable result is converged.
- No distributed transaction across PostgreSQL, files, model calls, or indexing is introduced.
- No semantic graph entity/edge is created, deleted, or rewired automatically. Existing
  compiled-page edge tier metadata under the exact dual-provenance predicate must nevertheless
  be promoted with its source page/chunks for I3; this is privacy-metadata reconciliation,
  not graph repair and does not rewrite historical `source_table/source_id` metadata.
- No migration or repair script is permitted: the live `pages`, `chunks`, and `edges` columns are sufficient, and crash recovery is file-backed.
- Plain SQL remains only in `src/db/repo.ts`; all SQL values are parameterized.
- Tests are offline and fictional. Synthetic tier-2 failure sentinels may exist only in
  mode-private temporary fixtures with unconditional cleanup; they may never use owner data
  or appear in logs, snapshots, result JSON, events, or retained fixtures.
- Every H1 test that exercises `brainSync()`, `compileNotes()`, archive parsing/writing,
  recovery enumeration, symlink rejection, or an injected filesystem/database/model failure
  must run inside an explicitly isolated `withPrivateDataDir()` fixture. The fixture creates a
  fresh `mkdtemp()` directory, forces its mode to `0700`, overrides the imported config's
  `dataDir` for the duration of the test, and restores the original value and removes the
  temporary tree in an unconditional `finally`; an isolated subprocess with the same private
  root is the only alternative. No such test may read, write, chmod, walk, symlink, or prune
  the repository's `data/`, `db-dump/`, or any other owner path, even to seed a fixture.
- Errors and results expose only fixed operation codes plus a page UUID or 16-character SHA-256 target hash; never title, raw path, body, model/provider text, recovery contents, or source text.
- Preserve `.env*`, `data/`, benchmark outputs, and every unrelated tracked or untracked file.
- Historical `DECISIONS.md` text is append-only.
- Two consecutive failed review/gate cycles in this area stop the tranche for owner review.
- A `final_reviewer_sol` BLOCK is binding and cannot be waived.

Normative semantics:

```text
normalizeCompiledNoteBody("a \r\nb\r\n\r\n") = "a \nb"
compiledNotePath("person", "A/B: 張", "11111111-2222-3333-4444-555555555555")
  = "derived/notes/person/a-b--11111111-2222-3333-4444-555555555555.md"
opaqueTargetHash(x) = first 16 lowercase hex characters of SHA-256(UTF-8(x))
```

`compiledNotePath()` uses this exact readable-slug algorithm before appending the full
canonical entity UUID: lowercase the readable name; replace each maximal run of characters
outside ASCII `[a-z0-9]` with one `-`; trim leading/trailing `-`; truncate to the first 60
ASCII characters and trim a trailing `-` introduced by truncation. If the result is empty,
use the validated full lowercase entity UUID as the slug. Validate the entity ID as a full
canonical UUID before slugging; the slug output contains only `[a-z0-9-]`, so separators,
slashes, dots, `..`, and traversal cannot be introduced by a readable name. The UUID suffix
remains the sole identity key even when the all-invalid fallback repeats it in the slug.

The codec tests pin this table (the final column is the slug segment):

| readable name | entity UUID | expected slug |
|---|---|---|
| `A/B: C` | `11111111-2222-3333-4444-555555555555` | `a-b-c` |
| `  --A..B-- ` | `11111111-2222-3333-4444-555555555555` | `a-b` |
| `A` repeated 59 times followed by `!B` | `11111111-2222-3333-4444-555555555555` | `a` repeated 59 times (the 60th truncated character is `-`, then trimmed) |
| `張偉 / …` | `11111111-2222-3333-4444-555555555555` | `11111111-2222-3333-4444-555555555555` |
| `../` | `22222222-3333-4444-5555-666666666666` | `22222222-3333-4444-5555-666666666666` |

The tests also assert that invalid/noncanonical entity UUIDs are rejected before any path is
returned and that no generated path component contains `/`, `\\`, `.`, or `..`.

`recognizeCompiledNote()` returns true when any one of these positive signals exists:

1. `source === COMPILED_NOTE_SOURCE`;
2. `compiledNoteIdentityFromPath(path)` succeeds;
3. `bodyMd` contains the exact `COMPILED_NOTE_MARKER` line and an exact `## Sources` heading with at least one UUID bullet.

`hasCompiledOwnershipEvidence()` is deliberately stricter than broad recognition: it is true
only for `source === COMPILED_NOTE_SOURCE` or canonical marker + Sources shape. A UUID path
alone remains a discovery/exclusion signal but is never sufficient authority to overwrite an
existing page or archive.

Recognition and source parsing normalize CRLF and bare CR to LF first. An exact
marker line and exact `## Sources` heading may be at offset zero or immediately after LF;
recognition requires at
least one canonical UUID bullet after the final such heading. The source parser accepts only
`- <canonical UUID>` lines beneath that final heading. Other text is ignored, IDs are
lower-cased and de-duplicated in first-seen order, and zero IDs means unresolved provenance
rather than tier 1. H5's SQL shape test must mirror these start-of-body/LF semantics.
`resolveCompiledNoteArchiveTarget()` applies `resolve()` + `relative()` containment and
returns null when the path is absolute, equals the brain root, or escapes it. Every archive
read/stat/write/unlink—not only recovery validation—must go through this helper.

It creates the parent at mode `0700`, opens sibling
`${target}.${process.pid}.${crypto.randomUUID()}.tmp` with flags `"wx"` and mode `0600`,
writes and `sync()`s the file, closes it, `rename()`s it over the target, `sync()`s the
parent directory, and unlinks only its own temporary sibling on error. It never follows a
temporary-file symlink and never logs `target`.
`createAtomicFileWriter()` is the deterministic test seam; production
`atomicWritePrivate()` binds it to `node:fs/promises`. Parent directories are created and
then forced to `0700`, including pre-existing directories. On injected write/file-sync/
close/rename failure, the prior target remains byte-for-byte and every opened handle is
closed; on parent-directory-sync failure, the complete renamed target is visible but the
call rejects so the recovery record remains. Every case removes only this invocation's temp
sibling and preserves unrelated siblings.
`assertNoSymlinkComponents()` walks the target and every existing component below the
canonical `config.dataDir` anchor with `lstat()`, rejects any symbolic link (including
`brain`/`tmp` roots), and checks the nearest existing ancestor's `realpath` remains within
the anchor's `realpath`. `ENOENT` is allowed only for the final not-yet-created suffix.
Archive and recovery callers apply this after lexical containment and before every
read/write/unlink; a symlinked intermediate directory cannot redirect an operation outside
the data root.
`preflightPrivateRoot()` performs lexical containment, `lstat`, component/realpath checks,
and regular-directory validation before any `readdir`, recursive walk, file read, or
`chmod`. With `create:true`, it validates the nearest existing ancestor first, creates the
directory, then repeats the full check before applying mode. It never chmods a symlink.
`brainSync()` preflights the brain root; recovery enumeration/writes preflight the recovery
root; archive reconciliation preflights the brain root. Failure is fixed and fail-closed:
zero enumeration, soft-delete, page/archive/chunk write, or model call.

`upsertPage()` defaults to the current behavior: preserve existing provenance and replace
content hash. H1 reconciliation passes
`{provenanceMode:"replace", contentHashMode:"preserve-existing", tierMode:"promote"}` so
page/body/status and exact `dream:notes` provenance are one explicit page write while an
existing hash is updated by the separately injectable `setPageContentHash()` step and tier is
`greatest(pages.tier, suppliedTier)`. A new row necessarily uses the supplied non-null
canonical hash/tier. Existing callers may ignore the additive `created` field.

All compiled-tier writers are monotonic SQL operations:

```sql
update pages set tier = greatest(tier, $target)
where id = $page_id and tier < $target

update chunks set tier = greatest(tier, $target)
where parent_type = 'page' and parent_id = $page_id and tier < $target

update edges set tier = greatest(tier, $target)
where (
  (source_table = 'pages' and source_id = $page_id)
  or (src_type = 'page' and src_id = $page_id)
)
and tier < $target
returning id
```

They return whether/how many rows changed; the `tier < target` predicate makes the second
sync a true zero-write no-op. `retierPageEdges()` returns the exact `RETURNING` row count,
not an attempted-call count. `compiledRepresentationTierEvidence()` reads the page plus all
existing page chunks and compiled-page edges under the same parenthesized predicate and
reports their maximum without an agent tier filter. No compiled-note path ever writes an
exact lower tier.

The evidence, lock, and postcondition queries repeat that predicate verbatim with `pageId`
as a bound value:

```sql
select max(tier) as edge_max_tier
from edges
where (
  (source_table = 'pages' and source_id = $page_id)
  or (src_type = 'page' and src_id = $page_id)
)

select id, tier
from edges
where (
  (source_table = 'pages' and source_id = $page_id)
  or (src_type = 'page' and src_id = $page_id)
)
order by id
for update

select count(*)::int as total,
       count(*) filter (where tier = $target)::int as at_target,
       max(tier) as max_tier
from edges
where (
  (source_table = 'pages' and source_id = $page_id)
  or (src_type = 'page' and src_id = $page_id)
)
```

After target selection/promotions, verification requires `total === at_target` and
`max_tier` null or equal to `target`. A separately seeded edge with only
`dst_type='page', dst_id=$page_id` is absent from evidence, locks, returned write count, and
postconditions; H1 never retargets an incident edge whose source/provenance is unrelated.

Every helper first locks the page row. `replacePageChunksMonotonic()` uses one database
transaction to `select ... for update` the page, its existing chunks, and every edge matched
by the exact dual-provenance predicate above, recomputes the maximum under those locks, and
inserts replacement chunks only at that effective tier. The max-only setters take the same
page-row lock before their guarded update. Thus even a promotion that committed while a stale
caller waited is observed before replacement; there is no transient tier-1 chunk rewrite.

`UpsertPageInput` is the exact concrete replacement for the current anonymous `Std`
intersection. Its camelCase fields map to `pages.body_md`, `content_hash`, `created_by`, and
`derived_from`; `PageSnapshot` remains the snake_case database shape. Every path match
includes active or deleted rows, and any successful upsert restores `status='active'`
without changing its UUID. `pageByPath()` and `pageById()` likewise include deleted rows for
recovery; only `activePagesForCompiledNoteReconciliation()` filters `status='active'`.

`activePagesForCompiledNoteReconciliation()` returns every active page without applying an
agent tier predicate. It is an on-box system-job read; TypeScript then applies
`recognizeCompiledNote({path: page.path, source: page.source, bodyMd: page.body_md})`. This
explicit adapter deliberately includes a canonical marker + Sources page
outside `derived/notes/`, as required by the approved enumeration contract.
`compiledSourceEvidence()` resolves a source UUID whenever its chunk exists, even if its
parent no longer has a `mentions` edge. It joins extant chunks back to parent-anchored
`mentions` edges for typed ownership and freshness, and returns every missing chunk UUID
explicitly. Its `resolved` rows are ordered by `chunk_updated_at`, `chunk_ord`, then chunk
UUID; `representative_parent_id` is the first resolved row's parent, allowing an imported
canonical archive with `derived_from = null` to restore provenance even when its entity is
no longer a current candidate.

There is exactly one `resolved` object per requested extant chunk. Aggregate all qualifying
ownership edges into that object's de-duplicated `entity_refs`; never let the SQL join
duplicate a chunk or skew ordering/representative provenance. Ownership matching is exact:

- for historical chunk-anchored metadata, require `e.source_table='chunks'` and
  `e.source_id = requested.id`;
- for parent-anchored metadata, retain an identity only when the requested chunk literally
  contains a nonblank canonical name or alias using
  `strpos(lower(chunk_text), lower(name_or_alias)) > 0`, the same literal rule H5 uses.

Those bullets resolve ownership for persisted Sources IDs only. They do not narrow the
compiled-page tier predicate: H1 still includes historical chunk-provenance edges through
their canonical `(src_type='page', src_id=pageId)` endpoint, matching H5's parent authority,
without treating an unrelated dst-only page endpoint as ownership.

An extant chunk still contributes tier and parent provenance when no ownership edge
qualifies. `mention_created_at` is the maximum qualifying edge timestamp for that chunk,
and `latest_mention_at` is the maximum of those per-chunk values.
`compiledEntityClusterEvidence()` uses the same compiled-page exclusion and
literal-name rule, de-duplicates source chunk UUIDs, and returns the maximum tier in the
current mention cluster for the supplied identities.

`withCompiledNotesLease()` reserves one postgres.js connection, takes blocking
`pg_advisory_lock(1296649541, 1)` before any recovery/page/candidate enumeration, runs
`work` using the normal pool, then unlocks and releases the reserved connection in nested
`finally` blocks. This is a process-wide lease, not a transaction across the model, database,
or filesystem. A process crash closes the reserved connection and releases the lock.

`withCompiledNoteTargetLease()` similarly takes a session advisory lock derived with
`hashtextextended('minime:compiled-note:' || targetKey, 0)`. Both `brainSync()` and H1
reconciliation use the normalized relative target path as the key. The lock spans only the
single on-box reconciliation flow (it is not a database transaction) and prevents those two
writers from interleaving tier snapshots/replacement. Once admitted, they re-read page,
chunk, edge, Sources, and current-cluster tier evidence before selecting a target tier.

The source queries share one private exclusion helper. A page-backed chunk is eligible only
when its parent page is active; pages with `source='dream:decision-digest'` and every page

## Reconciliation state machine

The implementation must follow this algorithm; the named operations are the failure codes
above and the barriers used by tests:

```ts
async function compileNotes(options = {}): Promise<CompileNotesSummary> {
  return withCompiledNotesLease(async () => {
    const recoveryListings = await listCompiledNoteRecoveryRecords();
    const pages = (await activePagesForCompiledNoteReconciliation()).filter(
      (page) => recognizeCompiledNote({
        path: page.path,
        source: page.source,
        bodyMd: page.body_md,
      }).recognized,
    );
    const candidates = await noteCandidates(MIN_CHUNKS);

    // Invalid records are results only. They are not deleted or used.
    // Valid recovery wins its entity key. Uniquely-owned legacy pages win over a new path.
    // Ambiguous legacy pages get their own page key and never claim a candidate.
    const work = await resolveWorkUnion(recoveryListings, pages, candidates);
    const results: NoteResult[] = recoveryListings
      .filter((listing) => !listing.valid)
      .map(invalidRecoveryResult);
    for (const item of work) {
      results.push(await reconcileWorkItem(item, mergedDeps(options)));
    }
    return summarize(candidates.length, results);
  });
}
```

`resolveWorkUnion()` applies this deterministic precedence:

```text
1. schema-valid recovery whose canonical/legacy target ownership also validates
2. one uniquely-owned slug-only legacy page for kind/entity
3. UUID-path page whose embedded UUID is kind/entity
4. current candidate at its UUID-suffixed path
```

A schema-valid recovery whose canonical or legacy target fails the database ownership checks
emits its own `identity_conflict` result and is excluded before precedence; it never
suppresses the canonical entity candidate.

An ambiguous legacy page uses `page:<page_id>` and is retained/repaired independently at
tier 2. A path/body identity conflict also uses its page key, is retained/promoted at tier 2,
returns `failed + identity_conflict`, and cannot claim or overwrite the entity's UUID path.
Identity-conflict handling may max-promote the already-existing safe database row/chunks/
compiled-page edges matched by the dual-provenance predicate, but never changes body, hash,
provenance, or any archive. In particular,
it never writes an archive target whose canonical path or body ownership conflicts.
Exception: a human/unrecognized page that merely occupies the canonical UUID path is not
compiler-owned material, so it receives zero mutation of any kind—no page, chunk, edge,
archive, tier, body, hash, or provenance write.
Every other item uses `entity:<kind>:<entity_id>`, so a recovery, page, and candidate for one
entity have one model opportunity. Work is sorted recovery first, then page ID/target hash
for deterministic tests.

`reconcileWorkItem()` returns exactly one final `NoteResult`. A converge-first recovery plus
one newer distillation is one work item and one counter contribution, never two results.
Status is decided from the work item's initial snapshot and the complete run:

```text
created   page was absent at entry and exists after successful convergence
updated   page existed and this run durably distilled a newer source snapshot
repaired  no newer distillation was needed and at least one representation/provenance changed
unchanged no model call and no target representation write
failed    the item's final required phase did not converge
```

An invalid recovery file contributes one `failed` result with only
`status`, `target_hash`, `code:"invalid_recovery_record"`; kind/tier/page ID are omitted
unless independently validated. For each valid work item:

```text
  LOAD
  Enter the target-path advisory lease, then reload page, every page-chunk tier, every
  dual-predicate compiled-page edge tier, Sources IDs/evidence, current entity-cluster
  evidence, current latest_mention_at, and the existing page.updated_at when a page is present. Snapshot that
  timestamp before any representation/provenance repair or write; it is a conservative legacy
  successful-page freshness baseline, not representation-consistency evidence. Only after
  safe-root preflight, load exact archive bytes if present.

AMBIGUOUS LEGACY
  Render pages.body_md with authoritative tier 2, reconcile page/hash/archive/chunks without
  a model call, and retain path/page ID. Return repaired + legacy_path_ambiguous only when a
  representation changed; otherwise unchanged + the same code.

VALID RECOVERY
  Converge its page, archive, and chunks once. Verify all representations. Delete the record.
  Reload current sources. If latest_mention_at > record.source_freshness_at or the ordered
  current source-ID set differs, and the cluster still has >= MIN_CHUNKS, permit exactly one
  new distillation pass. Otherwise return the one final created/repaired result.

  NO RECOVERY, PAGE EXISTS
  Before any convergence/repair, snapshot loaded page.updated_at and calculate stale =
  (current latest_mention_at > loaded page.updated_at) OR (ordered current source-ID set differs
  from persisted Sources IDs). Compute this once from the pre-repair snapshot. If stale and the
  cluster remains eligible, distill exactly once even when IDs are unchanged (a newer mention or
  alias edge can advance latest_mention_at). If not stale and only representations disagree,
  repair from pages.body_md without a model call. A representation/provenance repair later in
  this run never rewrites the snapshot or turns stale into fresh. If the IDs and freshness are
  unchanged and all DB/archive/chunk/provenance fields agree, return unchanged without a write
  or index call.

NO RECOVERY, NO PAGE
  If the current cluster is eligible, distill; otherwise there is no work item/result.

DISTILL
  Snapshot source IDs, representative parent ID, max tier, and latest_mention_at before the
  model call. Render the body with COMPILED_NOTE_MARKER and canonical Sources UUID bullets.
  Normalize/render the archive. Atomically persist a recovery record before page, archive,
  or chunk change. If persistence fails, return failed + recovery_write_failed.

CONVERGE
  0. while holding the target lease, re-read the complete tier floor; for an existing page,
     max-promote every dual-predicate compiled-page edge and page-chunk tier before changing
     the page; no exact-lower write exists
  1. upsertPage(..., provenanceMode=replace, contentHashMode=preserve-existing,
     tierMode=promote)
  2. setPageContentHash only when the loaded/current hash differs
  3. atomic archive sibling rename only when bytes differ or file is absent
  4. indexParent(...,{extractEdges:false,tierMode:"promote-page-floor"}) only when
     ord/text/tier differs from chunkMarkdown(body,title)
  5. idempotently retierPageEdges(pageId,tier) after indexing; count only rows returned by the
     exact dual-provenance predicate and do not create/delete/rewire or alter provenance
  6. reload page/archive/chunks/all dual-predicate edge tiers and verify exact page ID, active status, title,
     body, hash, source, creator, derived_from, bytes, chunk order/text, and max-only tier
     agreement; if any concurrent/evidence tier is higher, raise the target/rendered archive
     and reconverge once (1 -> 2 is the only possible escalation), never lower it
  7. remove the valid recovery file; unlink failure is recovery_remove_failed

FAIL
  Keep any valid recovery record. A repair-only item with no record remains discoverable
  from its recognized page on the next run. Emit one fixed code with page UUID or target
  hash. Never downgrade the failed item to unchanged or include the caught exception message.
```

An unsafe marker-recognized database path is retained and promoted (page, chunks, existing
dual-predicate compiled-page edge tier metadata) to tier 2 but receives
`failed + unsafe_archive_path`; no archive read/write/unlink occurs. A recovery-remove failure happens only after full verification,
leaves the valid record intact, and the next run verifies/retries removal with zero model
calls.
An unsafe brain/recovery root aborts before enumeration and returns one
`failed + unsafe_archive_path` result whose target hash is derived from the fixed label
`"compiled-note-root"`, never the raw root. `brainSync()` throws only
`UNSAFE_PRIVATE_ROOT`; neither path reaches soft-delete or a target write.
The compile summary is exactly candidates/created/updated/repaired/unchanged = 0,
failed = 1.

If sources change during the one additional distillation, converge that newly durable record
and return `source_changed_deferred`; the next run performs the next distillation. A valid
record whose target is already fully consistent is removed with zero model calls.

The no-recovery freshness baseline is deliberately the loaded `pages.updated_at` captured
before convergence. This adds no migration, archive field, or canonical frontmatter key: it
only preserves the existing successful-page timestamp long enough to detect a newer mention or
alias edge during this run. If a representation repair advances `updated_at`, the snapshot is
not rewritten; subsequent runs compare their newly loaded timestamp against later source
timestamps, so a future source change remains observable without treating repair metadata as a
source freshness signal.

## 2026-07-25 correction addendum — tier-0 absorbing quarantine

This append-only correction supersedes the plan's no-migration, `NoteTier = 1 | 2`,
max-only tier promotion, and unresolved-provenance-to-tier-2 assumptions. It does not
change archive bytes, recovery JSON, the pinned stack, or search weights.

- Tier 0 is an absorbing non-agent-material state. Explicit tier-0 page, chunk,
  accepted-edge, source, cluster, representation, recovery, or incoming frontmatter
  evidence cannot be promoted to tier 1 or 2 or reach search, graph/context reads,
  embeddings, extraction, model prompts, recovery persistence, or convergence.
- Migration 019 replaces migration 018's generic tier-read policies with
  `tier >= 1 AND tier <= app_allowed_tier()` for the same tables and roles. It changes
  no grants or revokes.
- Ordinary prose upserts and indexing reject tier 0 and invalid tiers. Generated
  brain-sync and compiler-owned database mirrors are transactionally quarantined by
  marking their page deleted at tier 0, setting descendant chunks and relevant
  provenance edges to tier 0, and clearing embeddings. Owner archive bytes are never
  modified, and human-owned collisions remain unchanged for opaque owner review.
- Brain sync classifies raw frontmatter before status, recognition, seen-path, upsert,
  or index behavior. Missing tier remains the legacy tier-1 default; explicit tier 0
  and invalid, ambiguous, duplicate-final, fractional, negative, or out-of-domain
  values are quarantined rather than normalized. Unresolved compiled-note provenance
  likewise causes generated database mirrors to be quarantined, while human-owned
  collisions remain unchanged.
- Compiled-note evidence carries both minimum and maximum tiers across candidates,
  accepted mention edges, Sources, clusters, and persisted representations. Tier 0
  blocks; unresolved or invalid evidence reports `source_evidence_unverifiable`.
  Blocked results omit `tier`.
- Explicit tier-0 or unverifiable generated recoveries are removed before model or
  canonical-target work. Removal failure retains the private record and performs zero
  target writes. A source that becomes unverifiable during convergence leaves the
  generated database representation quarantined while preserving archive bytes.
- One Unicode-aware ownership matcher requires letter/number boundaries for Latin
  names, preserves literal punctuation aliases, and intentionally permits CJK
  substring matching.

Validation is the H1 archive, brain-sync, recovery, provider-routing, role-policy,
search/privacy, full-project, typecheck, formatting, subsystem, and acceptance-gate
suite required by the correction brief.
