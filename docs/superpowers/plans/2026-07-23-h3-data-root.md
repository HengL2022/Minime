# H3 Repository-Stable Data Root Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Minime's default archive and every persistent/pre-image database dump resolve from the repository root, independent of the caller's working directory, while keeping restored plaintext artifacts private and temporary.

**Architecture:** `src/util/config.ts` exports one physical-realpath `REPO_ROOT` and
`DB_DUMP_DIR` and resolves unset, absolute, and relative `MINIME_DATA_DIR` values against
that root. TypeScript backup/repair consumers import those values; backup fsyncs and
atomically renames a private sibling dump, while Bash restore/promote scripts independently
derive the same physical root and use private workspaces with unconditional cleanup. Every
`pg_dump` receives individual connection parameters through a mode-`0600` ephemeral libpq
service file; child output is ignored/fixed-code only, and no database URL is placed on argv,
misused as `PGDATABASE`, or expanded in restore output.

**Tech Stack:** Bun/TypeScript, `node:path`, `node:fs/promises`, Bash 3.2, `pg_dump`, `psql`, restic, `bun test`.

## Global Constraints

- Start branch `codex/hardening-data-root` from the exact binding-reviewed H2 branch SHA,
  never from the original design branch or `80760f6`.
- Use the pinned ignored worktree `.claude/worktrees/hardening-data-root`, record its initial
  head as `START_SHA`, and scope every status, ledger, diff, gate, and review command to that
  worktree.
- `src/util/config.ts -> ../..` is the normative repository-root derivation, canonicalized
  through the physical filesystem so it equals shell `pwd -P` even when imported through a
  repository symlink.
- Unset, empty, or whitespace-only `MINIME_DATA_DIR` resolves to `<repo-root>/data`.
- An absolute override is normalized without changing its target.
- A relative override is trimmed and resolved against the repository root, never `process.cwd()`.
- Repo-root `.env` fallback and default data-root resolution use the same exported `REPO_ROOT`.
- `DB_DUMP_DIR` is `<repo-root>/db-dump`; it remains outside `data/`.
- `src/pipeline/backup.ts`, default `scripts/repair.ts`, and `scripts/promote-restore.sh` use that persistent dump root.
- Every persistent dump consumer calls the same private-root preflight before creating or
  opening a dump: the absolute intended path's immediate parent must already exist; every
  existing parent component is `lstat`-validated as a non-symlink directory, and the
  immediate parent's physical `realpath` must equal its lexical path. Only an absent final
  component may then be created non-recursively with mode `0700`; the final directory is
  re-`lstat`ed and re-realpathed before use. A symlink, non-directory collision, mode
  mismatch, or canonical-path mismatch fails with a fixed content-free code. No preflight
  follows, chmods, removes, or enumerates a symlink target.
- This protects pre-existing/static namespace collisions. A concurrent same-UID actor that
  mutates the namespace after validation is outside the threat boundary because that actor
  can also alter the code/configuration; no plan text claims race-proofness.
- `runRepair(..., { dumpDir })` remains supported for isolated tests.
- Plaintext dump directories are mode `0700`; dump/replay files are mode `0600` from creation via `umask 077`.
- `pg_dump` is invoked with no database positional argument and no `PGDATABASE=postgres://...`; a private mode-`0600` `PGSERVICEFILE` expands the configured PostgreSQL URI into individual libpq parameters and is removed on success, failure, early exit, and signal whenever the OS permits. A persistent refusal may leave only the validated mode-0600 artifact beneath its mode-0700 owner directory for harness/owner recovery; no path or error is emitted.
- The mandatory unmocked `pg_dump` test derives an explicit isolated `minime_test` URL from
  the test harness, proves `dbname=minime_test`, and refuses `/minime` before spawning. It
  never reads, connects to, or dumps the owner's live `minime` database.
- Service-file parsing is fail-closed: accept only `postgres:`/`postgresql:` URIs, preserve percent-decoded structural/query parameters and last-query-value precedence, reject nested `service`/`servicefile`, control characters, unrepresentable edge whitespace, malformed hosts/ports, and rendered lines longer than libpq's exact safe byte limit without printing the URL.
- PostgreSQL's service reader has a 1024-byte buffer including LF and terminating NUL.
  Therefore each rendered `key=value\n` byte sequence is at most 1022 UTF-8 bytes; reject
  1023 bytes or more using `Buffer.byteLength()`, never JavaScript character count.
- The same pure renderer backs TypeScript and the stdin-only shell bridge; the shell bridge never receives a connection URL on argv and never prints it.
- `restore-drill.sh` and `restore-pitr.sh` leave no plaintext dump or replay-error artifact after success, failure, early exit, or signal.
- Every `psql` invocation in `restore-drill.sh`, `restore-pitr.sh`, and
  `promote-restore.sh` uses a private mode-`0600` `PGSERVICEFILE` selected through
  `PGSERVICE=minime_ephemeral`; no URL-bearing `-d`/argv form is allowed. `ADMIN_URL`,
  `DRILL_URL`, `LIVE_URL`, and `RESTORE_URL` (or equivalents) may enter only the stdin bridge
  and never appear in argv, output, trace, heredoc, event, or dynamic instructions.
- Restore/promote diagnostics and handoff instructions use fixed safe labels/commands only;
  they do not print database, user, host, credential, URL, or dynamically resolved dump/path
  names.
- Backup publishes `db-dump/minime.sql` only by fsyncing and atomically renaming a private
  sibling temporary file; dump failure or signal removes the sibling when the OS permits and
  preserves the last good target. A persistent signal-time refusal may leave only the validated
  private sibling for harness/owner recovery, with the exact signal status and optional fixed
  diagnostic.
- Backup, snapshot, repair, and restore diagnostics are fixed content-free codes/messages.
  Child stdout/stderr, connection URLs, hosts, users, database names, and credentials are
  never returned, printed, heredoc-expanded, or persisted to events.
- Existing installations launched from the repository root keep the same physical paths; this branch moves no owner data.
- No new runtime dependency, migration, repair script, subsystem, or network call is introduced.
- Preserve unrelated tracked changes and every untracked user/agent file.

`ensurePrivateDumpDir(path)` is the one shared TypeScript preflight used by backup and repair.
It resolves the intended absolute path, requires the immediate parent to exist, walks every
existing parent component with `lstat` (rejecting symlinks and non-directories), and requires
`realpath(dirname(path)) === dirname(path)` before creating anything. It creates only an
absent final component non-recursively with mode `0700`, then re-`lstat`s and re-realpaths the
final directory, checks mode `0700`, and rejects any static symlink/non-directory/canonical
collision with a fixed `PrivateDumpDirError.rule`. The default `DB_DUMP_DIR` is the physical
`<REPO_ROOT>/db-dump`. It never follows, chmods, enumerates, or removes a symlink target.
Callers revalidate immediately before a writer opens a sibling and immediately before and
after publication. The preflight is intentionally not a guarantee against concurrent
same-UID namespace mutation after validation; that actor is outside this design's threat
boundary. All failures expose only `PrivateDumpDirError.rule`, never a path.

`parsePostgresUri()` implements the libpq URI grammar needed by existing
`DATABASE_URL` values rather than relying on WHATWG hostname normalization:

- schemes are exactly `postgres:` or `postgresql:`;
- percent decoding happens once, malformed escapes fail, and decoded C0/DEL bytes fail;
- user/password, database, IPv4/IPv6/Unix-socket host, port, comma-separated multi-host
  lists, and named query parameters are converted to individual service keys;
- named query parameters apply in source order with the last duplicate winning and can
  override structural `host`, `port`, `user`, `password`, and `dbname`, matching libpq URI
  semantics; `ssl=true` becomes `sslmode=require`;
- parameter names must match `^[a-z_][a-z0-9_]*$`; `service` and `servicefile` are rejected;
- empty values are retained, but values with leading/trailing ASCII whitespace are rejected
  because `pg_service.conf` would trim them;
- for every rendered line, `Buffer.byteLength(`${key}=${value}\n`, "utf8") <= 1022`; the
  LF consumes one byte and libpq's terminating NUL consumes the remaining buffer byte.
  A 1023-byte rendered line is rejected as `line_too_long` before a file is created.

Errors name only the violated rule and never include the URI or a decoded parameter value.
The renderer emits one fixed `[minime_ephemeral]` section with one parameter per line:
`host`, `port`, `user`, `password`, and `dbname` first when present, followed by remaining
query keys in lexical order. This order is deterministic but does not change libpq
precedence because each key appears once.

`registerEphemeralCleanup()` is the one process-local synchronous cleanup registry used by
service leases, repair pre-image files, backup sibling-stage dumps, and bridge temporary
directories. It accepts only an absolute path created by the caller, adds it before any
credential/dump bytes are written, installs one HUP/INT/TERM handler set on the
empty-to-nonempty transition, and returns an idempotent unregister function. Its optional
callback is `EphemeralCleanup = () => boolean`: a zero-argument closure captures the owned
path and performs only synchronous lifecycle work. One signal snapshots entries and runs all
callbacks exactly once in deterministic LIFO order, clears only callbacks that return true,
restores default signal handling, and re-sends the original signal once. A false callback is
not retried by a later registry signal: it remains only until this imminent termination and
may synchronously emit the exact content-free `ephemeral cleanup failed (signal)` diagnostic
once. The handler never logs a path, awaits a Promise, or swallows a signal; exit status is
HUP=129, INT=130, TERM=143 after the re-send. No caller/root/data/dump path may be registered.
There is no second lease/dump/repair signal registry and no caller-specific signal handler:
one registry, one handler set, one signal re-send.

`createLibpqService()` uses synchronous `mkdtempSync(join(tmpdir(), "minime-libpq-"))`,
registers that directory synchronously before the first await/callback or credential write,
then verifies/chmods the directory to `0700`, writes the service file with exclusive `"wx"`
mode `0600`, verifies the mode, and removes the whole directory from `dispose()` even after
partial creation. Its
`env()` copies the supplied environment (default `process.env`) and overwrites only
`PGSERVICE=minime_ephemeral` and `PGSERVICEFILE=<absolute-private-file>`; service-file values
override corresponding ambient `PG*` defaults by libpq contract.
It registers the lease directory through `registerEphemeralCleanup()` immediately after
`mkdtempSync()` with a synchronous `rmSync`/`lstatSync` callback; an optional test hook may
send HUP/INT/TERM at that exact boundary. `dispose()` is idempotent and uses the async verified
remover on normal paths; it unregisters only after the directory is confirmed absent. If both
attempts fail while the process remains alive, it returns a fixed failure; a later signal runs
the already-registered synchronous callback once, and no callback is described as armed for a
future signal after that termination. A persistent OS refusal may leave only the validated
private directory for owner/harness recovery, never an unvalidated or silently exposed path.

Register each lease directory synchronously immediately after `mkdtempSync()` and before the
first credential write. Backup registers its O_EXCL sibling-stage file immediately after
`openSync()` and before `createLibpqService()`; repair registers its pre-image before the first
child await; the bridge registers its private temporary directory before writing service bytes.
All four callers provide a synchronous callback for signal cleanup and use their async verified
remover only on normal paths; both share the same no-follow ownership predicates and absence
postcondition. Each unregisters only after confirmed ownership cleanup. Registry entries are
absolute paths created by the owning module only; never register a caller path, repository root,
data root, or dump root. Do not use async cleanup inside a signal handler, do not swallow/relabel
signals, and do not install handlers while the registry is empty.

Replace the path import and root/data resolution with:

```ts
import { lstat, mkdir, realpath } from "node:fs/promises";
import { realpathSync } from "node:fs";
import { dirname, isAbsolute, normalize, resolve } from "node:path";
import { fileURLToPath } from "node:url";

export const REPO_ROOT = realpathSync(
  resolve(dirname(fileURLToPath(import.meta.url)), "..", ".."),
);
export const DB_DUMP_DIR = resolve(REPO_ROOT, "db-dump");
export type PrivateDumpDirRule =
  | "symlink"
  | "not_directory"
  | "not_canonical"
  | "mode"
  | "filesystem";

export function resolveDataDir(value: string | undefined): string {
  const trimmed = value?.trim() ?? "";
  if (!trimmed) return resolve(REPO_ROOT, "data");
  return isAbsolute(trimmed) ? normalize(trimmed) : resolve(REPO_ROOT, trimmed);
}

export class PrivateDumpDirError extends Error {
  constructor(readonly rule: PrivateDumpDirRule) {
    super(`private dump root rejected (${rule})`);
  }
}

export async function ensurePrivateDumpDir(path: string): Promise<void> {
  const intended = resolve(path);
  const parent = dirname(intended);
  let component = parent;
  while (true) {
    let parentStat;
    try {
      parentStat = await lstat(component);
    } catch {
      throw new PrivateDumpDirError("filesystem");
    }
    if (parentStat.isSymbolicLink()) throw new PrivateDumpDirError("symlink");
    if (!parentStat.isDirectory()) throw new PrivateDumpDirError("not_directory");
    const next = dirname(component);
    if (next === component) break;
    component = next;
  }
  try {
    if ((await realpath(parent)) !== parent) throw new PrivateDumpDirError("not_canonical");
  } catch (error) {
    throw error instanceof PrivateDumpDirError
      ? error
      : new PrivateDumpDirError("filesystem");
  }

  let initial;
  try {
    initial = await lstat(intended);
  } catch (error) {
    if ((error as NodeJS.ErrnoException).code !== "ENOENT")
      throw new PrivateDumpDirError("filesystem");
    try {
      await mkdir(intended, { mode: 0o700 });
    } catch {
      throw new PrivateDumpDirError("filesystem");
    }
    initial = await lstat(intended);
  }
```

```ts
function validateOutputParent(outputPath: string): string | undefined {
  const parent = dirname(outputPath);
  if (!isAbsolute(parent)) return undefined;
  try {
    let component = parent;
    for (;;) {
      const entry = lstatSync(component, { throwIfNoEntry: false });
      if (!entry || !entry.isDirectory() || entry.isSymbolicLink()) return undefined;
      const next = dirname(component);
      if (next === component) break;
      component = next;

    const physicalParent = realpathSync(parent);
    const owner = statSync(physicalParent);
    if ((owner.mode & 0o777) !== 0o700) return undefined;
    if (typeof process.getuid === "function" && owner.uid !== process.getuid()) return undefined;
```

```ts
function ownedDumpTempSync(path: string, dumpDir: string): boolean {
  for (let attempt = 1; attempt <= 2; attempt += 1) {
    try {
      const parent = lstatSync(dumpDir, { throwIfNoEntry: false });
      const before = lstatSync(path, { throwIfNoEntry: false });
      if (!parent || !before) return true;
      if (!parent.isDirectory() || before.isSymbolicLink() || !before.isFile()) return false;
      if (dumpTempRemoveSyncForTest && !dumpTempRemoveSyncForTest(path, attempt)) continue;
      if (!dumpTempRemoveSyncForTest) rmSync(path, { force: true });
      const after = lstatSync(path, { throwIfNoEntry: false });
      if (!after) return true;
    } catch {
      // Fixed synchronous cleanup failure; retry once before the signal is re-sent.
    }
  }
  return false;
}

async function removeOwnedDumpTemp(path: string, dumpDir: string, attempt: number): Promise<void> {
  const parent = await lstat(dumpDir).catch((error: unknown) => {
    if ((error as NodeJS.ErrnoException).code === "ENOENT") return null;
    throw error;
  });
  const before = await lstat(path).catch((error: unknown) => {
    if ((error as NodeJS.ErrnoException).code === "ENOENT") return null;
    throw error;
  });
  if (!parent || !before) return;
  if (!parent.isDirectory() || before.isSymbolicLink() || !before.isFile()) {
    throw new Error("owned dump rejected");
  }
  if (dumpTempRemoveForTest) await dumpTempRemoveForTest(path, attempt);
  else await rm(path, { force: true });
  const after = await lstat(path).catch((error: unknown) => {
    if ((error as NodeJS.ErrnoException).code === "ENOENT") return null;
    throw error;
  });
  if (after) throw new Error("owned dump remains after removal");
}

function registerDumpTemp(temp: string, dumpDir: string): () => void {
  return registerEphemeralCleanup(temp, () => ownedDumpTempSync(temp, dumpDir));
}

      unregister?.();

      // Fixed cleanup failure; retry once without exposing the path or error text.
    }
  }
```

```ts
function removePreImageSync(file: string, dumpDir: string): boolean {
  for (let attempt = 1; attempt <= 2; attempt += 1) {
    try {
      const parent = lstatSync(dumpDir);
      const before = lstatSync(file);
      if (!parent.isDirectory() || before.isSymbolicLink() || !before.isFile()) return false;
      rmSync(file, { force: true });
      if (!lstatSync(file, { throwIfNoEntry: false })) return true;
    } catch (error: unknown) {
      if ((error as NodeJS.ErrnoException).code === "ENOENT") return true;
    }
  }
  return false;
}

async function removePreImageAsync(file: string, dumpDir: string): Promise<boolean> {
  for (let attempt = 1; attempt <= 2; attempt += 1) {

      const parent = await lstat(dumpDir).catch((error: unknown) => {
        if ((error as NodeJS.ErrnoException).code === "ENOENT") return null;
        throw error;

      const before = await lstat(file).catch((error: unknown) => {
        if ((error as NodeJS.ErrnoException).code === "ENOENT") return null;
        throw error;

      if (!parent.isDirectory() || before.isSymbolicLink() || !before.isFile()) return false;
```

```ts
  }
  if (!Array.isArray(candidate.ids) || !candidate.ids.every((id) =>
    typeof id === "string" && /^[A-Za-z0-9_-]{1,128}$/.test(id))) {
    return undefined;
  }
  const counts: Record<string, number> = {};
  for (const [key, count] of Object.entries(candidate.counts)) {
    if (!/^[a-z][a-z0-9_]*$/.test(key) || typeof count !== "number" ||
      !Number.isSafeInteger(count) || count < 0) return undefined;
    counts[key] = count;
  }
  return { counts, ids: candidate.ids.slice() as string[] };
}

async function repairFailure(
  verb: string,
  code: string,
  message: string,
): Promise<number> {
  try {
    await audit(verb, { phase: "failed", code, counts: {}, ids: [] });
  } catch {
    // Audit transport failure is intentionally folded into the same fixed phase.
  }
  console.error(message);
  return 1;
}

export async function runRepair(
  scriptName: string,
  args: string[],
  opts?: { dumpDir?: string },
): Promise<number> {
  const verb = `repair:${scriptName}`;
  // Committed-name/HEAD checks return their existing fixed code and the same
  // empty counts/ids shape; they never include the rejected name/path.
  const mod = await loadCommittedRepairModule(scriptName, args);
  if (!mod) return repairFailure(verb, "repair_not_committed", "repair failed (fixed code: repair_not_committed)");

  let backup: string | null;
  try {
    backup = await preImageDump(scriptName, resolveRepairDumpDir(opts?.dumpDir));
  } catch {
    backup = null;
  }
  if (!backup) {
    return lastPreImageFailure === "cleanup"
      ? repairFailure(verb, REPAIR_CLEANUP_FAILURE_CODE, REPAIR_CLEANUP_FAILURE_MESSAGE)
      : repairFailure(verb, REPAIR_BACKUP_FAILURE_CODE, REPAIR_BACKUP_FAILURE_MESSAGE);
  }

  let rawSummary: unknown;
  try {
    rawSummary = await mod.run(args);
  } catch {
    return repairFailure(verb, REPAIR_MODULE_FAILURE_CODE, REPAIR_MODULE_FAILURE_MESSAGE);
  }
  const summary = safeSummary(rawSummary);
  if (!summary) {
    return repairFailure(verb, REPAIR_INVALID_SUMMARY_CODE,
      "repair failed (fixed code: repair_invalid_summary)");
  }
  try {
    await audit(verb, { phase: "complete", code: "repair_complete", ...summary });
  } catch {
    return repairFailure(verb, REPAIR_CLEANUP_FAILURE_CODE, REPAIR_CLEANUP_FAILURE_MESSAGE);
  }
  return 0;
}
```

```ts
function injectCleanupEntryTrace(body: string, script: string): string {
  const functionName = script === "promote-restore.sh" ? "cleanup_promote" : "cleanup";

function readFixtureFiles(root: string, ignoredDirectories: readonly string[] = []): string[] {
  const rootReal = realpathSync(root);
  const files: string[] = [];
  const maxFiles = 4096;
  const maxBytes = 4 * 1024 * 1024;
  const visit = (directory: string): void => {
    if (files.length > maxFiles) throw new Error("fixture file bound exceeded");
    for (const entry of readdirSync(directory, { withFileTypes: true })) {
      const path = join(directory, entry.name);
      const stat = lstatSync(path);
      if (stat.isSymbolicLink()) continue;
      if (stat.isDirectory()) {
        if (ignoredDirectories.includes(path)) continue;
        visit(path);
      } else if (stat.isFile() && stat.size <= maxBytes) {
        files.push(readFileSync(path, "utf8"));
      }
    }
  };
  visit(rootReal);
  return files;
}
```

Shell utility boundary policy (Bash 3.2): each restore-drill, restore-pitr, and
promote-restore prologue begins with `umask 077` and empty ownership variables, resolves
cleanup-only absolute candidates (`/bin/rm` or `/usr/bin/rm`, plus fixed `/bin`/`/usr/bin`
`mktemp`, `cat`, `cut`, `tr`, `sort`, and `tail`) using shell builtins, and exits with its
fixed `cleanup_dependency` code before allocation if any required candidate is unavailable.
Define root-contained `remove_owned`, `remove_owned_file`, `best_effort_cleanup`, and the
cleanup function using only those resolved paths before installing EXIT/HUP/INT/TERM traps.
`remove_owned(target, root, expectedBase)` requires exact basename equality and lexical plus
physical parent containment.  `remove_owned_file(target, root, trustedPrefix)` requires the
same containment, a regular non-symlink target, and uses the quoted-prefix case pattern
`case "$base" in "$trustedPrefix"*)`; it never accepts an arbitrary glob argument.  Both use
the fixed absolute `rm` with two bounded retries and confirm lstat absence before success.
`best_effort_cleanup(target, root, prefix?)` dispatches to the exact-basename directory
remover or the prefix file remover; it never infers a glob from an untrusted target.
Only after the traps exist may the script allocate its workspace with the resolved `mktemp`;
only after allocation may it create `UTILITY_STDERR` and the capture helpers. No trap may
reference an undefined function, variable, or ambient PATH command. The cleanup callback is
therefore valid even for TERM immediately after `mktemp` and before `chmod`.

Before those traps or any allocation, the prologue validates `TMPDIR` (or `/tmp`) as an
absolute existing directory, rejects a relative value with the same fixed `failed (workspace)`
diagnostic, and canonicalizes it once with builtin `cd`/`pwd -P` into `TEMP_ROOT`. Every
trusted `mktemp` template and every cleanup root then uses only `$TEMP_ROOT`; no raw
`${TMPDIR:-/tmp}` expression may reach `mktemp` or a trap. This makes lexical `/tmp` and
physical `/private/tmp` (and equivalent `/var` aliases) the same ownership fence while
preserving the exact `minime-private.XXXXXX`/`minime-promote-libpq.XXXXXX` prefixes. The
canonical root must itself be a non-symlink directory, so the physical parent and retry/
absence checks remain stable under symlink aliases.
